# Profiling Traces

This directory stores GPU profiling traces and inference breakdown artifacts.
It currently holds one legacy Nsight Systems trace from distributed FSDP + LoRA
training alongside the **H100 Inference Profiling Runbook (WP-5)** for
capturing Nsight Compute (`ncu`), SASS, Nsight Systems (`nsys`), and
multi-GPU tensor-parallel decode profiles.

---

## H100 Inference Profiling Runbook (WP-5)

### 1. Nsight Compute (`ncu`) Roofline, Stalls & SASS Inspection

`benchmarks/profile_ncu.py` brackets a single decode kernel launch with
`cudaProfilerStart`/`cudaProfilerStop` and collects roofline, tensor-pipe,
L2 cache, occupancy, and warp-stall counters across implementations (`v3`, `v4`,
`v4_fp8`, `tc`, `tc_fp8`, `triton`, `triton_fp8`, `paged_triton`, `paged_fp8`,
`quest`, `quest_fp8`, `flashinfer`, `sdpa`).

```bash
# Default ncu roofline + stall sweep (v4, tc, tc_fp8, triton, triton_fp8, paged_triton)
python benchmarks/profile_ncu.py --ncu --ctx 32768

# Parse `ncu --csv` output into a Markdown summary table and save raw + formatted output
python benchmarks/profile_ncu.py --ncu --ncu-csv --ctx 32768 --ncu-out profiles/NCU_PROFILE.md

# Profile a specific kernel implementation with custom ncu sections
ncu --profile-from-start off -k regex:_decode_split_kernel -c 1 --section SpeedOfLight \
    python benchmarks/profile_ncu.py --impl triton_fp8 --ctx 32768

# Inspect compiled CUDA SASS instructions (HMMA / LDGSTS / LDG.E.128) via cuobjdump
python benchmarks/profile_ncu.py --sass --sass-out profiles/SASS_SUMMARY.md
```

Collected `ncu` metrics:
- `gpu__time_duration.sum`
- `dram__throughput.avg.pct_of_peak_sustained_elapsed`
- `dram__bytes_read.sum`
- `sm__inst_issued.avg.pct_of_peak_sustained_active`
- `sm__pipe_tensor_op_hmma_cycles_active.avg.pct_of_peak_sustained_active`
- `smsp__warp_issue_stalled_long_scoreboard_per_instruction_executed.avg`
- `smsp__warp_issue_stalled_mio_throttle_per_instruction_executed.avg`
- `lts__t_sector_hit_rate.pct`
- `sm__warps_active.avg.pct_of_peak_sustained_active`

### 2. Nsight Systems (`nsys`) End-to-End Decode Breakdown

`benchmarks/profile_e2e_nsys.py` annotates a `Qwen3-8B` single-step decode
pass with NVTX ranges (`Decode_Step` outer range containing `Embedding`,
`RMSNorm`, `QKV_Proj`, `RoPE_KV_Append`, `Quest_Page_Select`,
`Paged_Attention`, `O_Proj`, `MLP_SwiGLU`, and `LM_Head`) and writes a
per-component latency/percentage breakdown table.

```bash
# Run NVTX-annotated nsys sweep across batch sizes and context lengths and write Markdown report
python benchmarks/profile_e2e_nsys.py --nsys-sweep --out profiles/INFERENCE_PROFILE.md

# Capture a standalone Nsight Systems trace for a single decode configuration
nsys profile --trace=cuda,nvtx,osrt --capture-range=cudaProfilerApi \
    --capture-range-end=stop -o profiles/e2e_decode_b16_64k \
    python benchmarks/profile_e2e_nsys.py --method paged_fp16 --batch 16 --ctx 65536

# Lightweight CUDA-events fallback sweep when nsys is unavailable
python benchmarks/profile_e2e_nsys.py --nsys-sweep --cuda-events --out profiles/INFERENCE_PROFILE.md
```

### 3. Multi-GPU Tensor-Parallel (`TP >= 2`) Decode & NCCL Overlap

`benchmarks/bench_tp_decode.py` measures `torch.distributed` NCCL `AllReduce`
(`TP_AllReduce_Attn`, `TP_AllReduce_MLP`) and decoder-layer compute overlap
(`TP_Paged_Attn`, `TP_MLP_SwiGLU`), including CUDA Graph capture over NCCL
(when NCCL >= 2.19).

```bash
# Run TP=2 decode benchmark via standalone torch.multiprocessing.spawn
python benchmarks/bench_tp_decode.py --tp 2

# Launch via torchrun (e.g., TP=4)
torchrun --nproc_per_node=4 benchmarks/bench_tp_decode.py --shape qwen3-8b

# Capture an nsys trace bracketed around steady-state TP=2 decode steps
nsys profile --trace=cuda,nvtx,osrt --capture-range=cudaProfilerApi \
    -o profiles/tp2_decode \
    torchrun --nproc_per_node=2 benchmarks/bench_tp_decode.py --nsys-bracket --steps 16

# CPU-only partition and shard-equivalence validation (no GPUs required)
python benchmarks/bench_tp_decode.py --dry-run-cpu --shape qwen3-8b --tp 2
```

## Legacy Training Trace (`train/train_fsdp_lora.py`)

This directory also retains one legacy Nsight Systems trace captured during
distributed training of the FSDP + LoRA harness on dual NVIDIA H200 NVLink
(unrelated to the inference engine benchmarks above).

| Field | Value |
|-------|-------|
| Node | g213 |
| GPUs | Dual NVIDIA H200 NVL |
| Interconnect | NVLink |
| OS | Rocky Linux 9.3 |
| Driver | 580.82.07 |

### Trace

**[`ifsdp_h200_nvlink_trace.nsys-rep`](ifsdp_h200_nvlink_trace.nsys-rep)**

Generated by [`train/train_fsdp_lora.py`](../train/train_fsdp_lora.py) (legacy training trace).

| Property | Value |
|----------|-------|
| Model | 4× `LlamaStyleDecoderLayer` (dim=8192, SwiGLU MLP) |
| LoRA adapters | Q / K / V / O projections, rank=16, alpha=32 |
| Input shape | `[8, 2048, 8192]` |
| FSDP wrap policy | `ModuleWrapPolicy({LlamaStyleDecoderLayer})` |
| Warmup iterations | 2 |
| Steps profiled | ~12 |
| NVTX top-level range | `End_to_End_FSDP_Optimization_Step` |

### NCCL Communication Summary

| Metric | Value |
|--------|-------|
| AllGather avg (per layer) | 22.0 ms |
| ReduceScatter avg (per layer) | 22.9 ms |
| NCCL % of wall time | 3.2% |
| Typical GEMM kernel duration | 45–162 ms |
| Compute-to-communication ratio | ~30:1 |

`ModuleWrapPolicy({LlamaStyleDecoderLayer})` shards each decoder layer
independently, allowing PyTorch FSDP to overlap the AllGather for layer N+1
with the backward compute of layer N.
The result is that NCCL collectives account for only **3.2% of wall time**
against 45–162 ms GEMM kernels — a compute-to-communication ratio of ~30:1.

### NVTX Ranges

The following ranges are annotated in the trace for per-phase attribution:

- `End_to_End_FSDP_Optimization_Step`
- `Forward_Pass_Compute`
- `Backward_Pass_Compute_and_Comm_Overlap`
- `Optimizer_Parameter_Updates`

### How to Open

```bash
# Command-line stats — no GUI required
nsys stats profiles/ifsdp_h200_nvlink_trace.nsys-rep

# Interactive GUI
nsys-ui profiles/ifsdp_h200_nvlink_trace.nsys-rep
```
